# ADR-0001：可信单机推理 Appliance 与后续优化原则

- 状态：Accepted
- 日期：2026-07-31
- 决策者：项目维护者

## 背景

本项目已经覆盖模型选型、制品完整性、llama.cpp CUDA 运行、Profile、验收、候选发布、
本机运维和 ModelPort 集成。随着能力增加，项目面临三个风险：

1. 从单机推理栈无边界扩张为集群或多租户平台；
2. 配置、证据和运维入口继续增加，导致维护者难以判断真正的权威来源；
3. 控制面主要由多个 Python/Shell 入口组成，难以实现跨进程中断恢复和完整故障注入。

本 ADR 固定未来 6–12 个月的产品边界和优化原则。具体实施任务见
[项目优化路线图](../ROADMAP.md)。

## 决策

### 1. 产品定位

本项目定位为可信的单机本地推理 Appliance/参考实现，核心价值是：

- 在受支持主机上给出保守、可解释的模型与容量建议；
- 使用不可变制品身份和固定运行配置；
- 部署、验收、恢复和证据能够复现；
- 默认 fail-closed，并保持所有服务 loopback-bound。

本项目不承担集群调度、多租户、高可用、业务工具执行、公共网络入口、计费或通用网关职责。

### 2. 优化优先级

所有改动按以下顺序取舍：

```text
安全与可恢复性
  > 可复现性与证据可信度
  > 易用性
  > 性能
  > 新功能
```

性能收益不能作为配置漂移、不可恢复变更或证据降级的理由。

### 3. 支持矩阵

正式支持范围冻结为：

- Linux x86_64 + 单 NVIDIA GPU；
- WSL2 x86_64 + 单 NVIDIA GPU，并使用独立的 WSL 验收与恢复证据。

CPU、AMD、Apple Silicon、多 GPU、共享 GPU 只能得到只读规划结果。没有真实硬件、维护者、
完整验收和独立 Profile 时，不得通过容量覆盖或通用 Compose 参数宣布支持。

### 4. 公共接口与控制面

- 增加统一 `./stack` CLI 作为普通用户和 Agent 的公共入口；
- 控制面逐步迁移到一个正式 Python package；
- Shell 降级为兼容包装或必要的系统探针；
- 第一次 `plan` 保持 Python 标准库运行时依赖，不要求安装开发工具；
- 旧命令代理到新 CLI 至少一个弃用周期，不进行一次性重写。

公共命令必须提供稳定的结构化结果、错误码和退出码。人类文本只是结构化结果的渲染层。

### 5. 配置权威来源

- `catalog/models.json` 继续负责模型、制品、容量与许可证；
- 新增带 schema 的类型化运行规范，负责 Slot、上下文、KV、Batch 和缓存；
- `.env` Profile、Dashboard baseline 和 manifest 配置段由权威来源生成或严格校验；
- Compose 只保留通用运行模板，不复制模型业务默认值；
- ModelPort 契约只能通过双仓库兼容迁移更新。

### 6. 运行变更与恢复

部署、Profile 切换和串行候选发布升级为持久化事务状态机。每一步原子记录：

- 事务 ID 与目标；
- 原生产容器和 Profile；
- 当前状态；
- 已完成动作；
- 下一恢复动作。

进程异常、Docker daemon 中断、WSL 关闭或主机重启后，下一次执行必须先 reconciliation，
不能仅依赖 Shell `trap`。

### 7. 测试分层

- 无 GPU 的 hermetic 故障注入集成测试负责控制面状态转换；
- quick/standard/full 负责真实模型、GPU、质量和跨仓库数据面；
- 控制面测试覆盖下载中断、错误哈希、锁冲突、磁盘不足、环境污染和每个事务失败点；
- 真实性能门限只属于具体硬件 deployment manifest，不设置虚假的跨硬件统一 SLA。

### 8. 证据分层

- Local acceptance：本机使用的短期、配置绑定证据；
- Reusable validation：可提升 Catalog 状态的 canonical attestation。

可复用验证额外要求干净 Git commit、完整测试摘要、硬件/驱动、制品、镜像、配置身份和签名。
仅有自哈希的本机证据不能把 `estimated` 提升为 `validated`。

### 9. 运维凭据隔离

目标架构为：

```text
ModelPort 最小权限聚合 API
        -> 短生命周期 Collector
        -> 脱敏快照/SQLite
        -> 零凭据 Dashboard
```

Dashboard 不得持有 ModelPort 管理员凭据。长期凭据逐步迁移到 systemd credentials 或受支持的
本机密钥环；`.env` 仅作为兼容导入格式。

### 10. 供应链与离线复现

供应链状态拆分为：

- `identity-verified`；
- `publisher-verified`；
- `license-reviewed`。

项目将记录来源元数据和许可证快照，在上游提供签名时验证签名，并支持可校验的离线 bundle。
SHA256 不再被描述为发布者信任或许可证审查的替代品。

### 11. 性能与存储

- 性能校准只生成候选 Profile，不在线自动应用参数；
- 生产始终运行固定、命名、可哈希的 Profile；
- 存储治理采用引用感知 GC，默认 `--dry-run`；
- 当前生产、未完成事务和最近成功回滚锚点永远不能被 GC；
- 不执行后台静默删除。

### 12. 版本和跨仓库协同

- CLI、配置、证据、bundle 和 Provider contract 分别版本化；
- N-1 格式可以读取或显式迁移，但不再生成；
- 禁止静默迁移；迁移必须备份并支持回滚；
- ModelPort 通过版本化契约包和兼容夹具协同，不使用 Git submodule 或相邻目录作为正式依赖。

## 首版工程目标

- `stack plan` 离线、只读，常规情况下 5 秒内完成；
- 所有配置错误在下载或停机前发现；
- 并发运行变更全部被锁或事务拒绝；
- 失败候选能够恢复原生产 Profile；
- 主机中断后能够识别未完成事务并自动进入恢复；
- 错误字节数或哈希的制品发布率为零；
- 非 loopback 暴露在发布门禁中失败；
- 控制面状态机无需 GPU 即可在 CI 完整覆盖；
- 验收、事务和运维证据不保存真实 Prompt、回答或凭据。

## 影响

正面影响：

- 项目边界明确，避免向无人维护的平台能力扩张；
- 配置和证据更容易解释与审计；
- 主机级中断恢复不再依赖单个 Shell 进程存活；
- 普通用户获得更简单的入口，维护者仍保留底层诊断能力。

代价与风险：

- Python 控制面和事务迁移需要较长的兼容周期；
- 类型化配置生成器会改变现有文件维护方式；
- 最小权限 ModelPort operations API 需要双仓库协作；
- 可复用签名证据和离线 bundle 会增加发布流程成本；
- 在基础可靠性工作完成前，需要主动拒绝新平台和新后端需求。

## 明确不做

在本 ADR 被替代前，不实施：

- Kubernetes、远程多节点调度或高可用控制面；
- 在线自动改变 KV、上下文、Batch 或 Slot；
- 未经独立验收的 CPU/AMD/Apple Silicon/多 GPU 自动部署；
- Dashboard 直接执行运维动作；
- 为方便而绕过 `readyToDeploy`、完整性检查或显式批准。
